# 개념

WayScanner는 위험 요소가 있는 2D 격자 지도에서 로봇의 안전 경로와 도착 시 배터리 잔량을 함께 다루는 시뮬레이터다. 경로를 찾는 일과 배터리를 예측하는 일을 분리하되, 예측은 항상 확정된 경로에서만 나온다.

## 무대

- 지도는 2차원 격자다.
- 격자 위에는 출발지, 목적지, 일반 장애물, 위험 점이 있다.
- 위험 점은 지진, 화재, 방사능처럼 종류가 다를 수 있으나, 구역을 만들 때는 같은 종류의 금지 점으로 다룬다. 종류별 가중치는 아직 정하지 않았다.
- 위험 점은 무작위로 발생한다고 가정한다. 발생 규칙(개수, 분포, 시간)은 구현 단계에서 정한다.

## 1. 위험 구역 설정

담당: 팀원. 방법의 이름은 Convex Hull, 그중 Graham Scan이다.

맵에 위험 점이 여러 개 생기면, 그 점들 전부를 포함하는 **가장 작은 볼록 다각형**을 구한다. 합의된 표현은 "점들의 가장 외곽을 잇는 최소 크기의 볼록 다각형"이다. 흩어진 점 하나하나를 장애물로 두지 않고, 하나의 거대한 금지 구역(Keep-out Zone)으로 묶는다.

이 다각형의 내부와 경계는 로봇이 들어가거나 지나갈 수 없는 영역이다. 위험 구역 안이나 경계 위에 출발지 또는 목적지가 놓이면 유효하지 않은 위치로 처리하고, 경로를 찾지 못한 것으로 본다.

볼록 다각형으로 묶으면 오목하게 파인 안전한 골목도 금지 구역에 포함될 수 있다. 그 보수적인 선택을 이 프로젝트의 안전 기준으로 둔다. 더 타이트한 구역(오목 다각형, 점별 반경)은 이번 합의 범위가 아니다.

## 2. 최적 회피 경로 탐색

담당: 본인. 방법의 이름은 A*다.

출발지부터 목적지까지, 일반 장애물과 위에서 만든 볼록 위험 구역을 **동시에** 우회하는 경로를 구한다. 목표로 둔 것은 그 제약 안에서의 최단 경로다.

탐색은 두 값을 함께 본다.

- `g(n)`: 출발지에서 현재 위치까지 실제로 들인 이동 비용
- `h(n)`: 현재 위치에서 목적지까지 예상 거리(휴리스틱)
- 평가: `f(n) = g(n) + h(n)`

`h(n)`이 실제 남은 비용보다 크지 않아야 최단 경로를 보장할 수 있다. 어떤 거리(맨해튼, 유클리드 등)를 쓸지, 격자에서 대각 이동을 허용할지는 구현 전에 정한다. 이 문서에는 절차를 적지 않는다.

경로를 찾지 못하는 경우(목적지가 금지 구역 안이거나, 장애물에 막힌 경우)는 실패로 두고, 배터리 예측으로 넘어가지 않는다.

## 3. 배터리 소모 실시간 예측

담당: 본인. 방법의 이름은 선형 회귀(Linear Regression)다.

A*가 확정한 경로에서 두 가지를 뽑는다.

- 총 이동 거리
- 방향 전환(회전) 횟수

이 두 값이 예측 모델의 입력(feature)이다. 모델은 미리 학습되어 있다고 가정하고, 시뮬레이터는 매 경로가 확정될 때마다 그 모델에 두 값을 넣어 **목적지 도착 시 예상 배터리 잔량(%)** 을 화면에 낸다. "실시간"은 경로가 바뀔 때마다 다시 계산해 보여 준다는 뜻이지, 학습을 매 프레임 다시 한다는 뜻이 아니다.

아직 정하지 않은 것:

- 잔량의 기준이 되는 초기 배터리(100% 고정인지, 시나리오마다 다른지)
- 거리와 회전을 어떤 단위로 셀지(칸 수, 실제 길이, 90도 단위 회전만 셀지)
- 학습 데이터를 어디서 가져올지, 모델 파일을 어떤 형태로 둘지
- 잔량이 0 아래나 100 위로 나오는 경우를 어떻게 보여줄지

선형 회귀는 해석이 단순하다는 이유로 선택했다. 거리와 회전이 늘면 잔량이 줄어드는 방향이 나와야 한다. 그 방향이 뒤집히면 모델이 아니라 입력 정의를 먼저 의심한다.

## 데이터가 흐르는 방향

```text
위험 점들
  -> 볼록 금지 구역
       + 일반 장애물, 출발지, 목적지
            -> 회피 경로 (없으면 여기서 종료)
                 -> 총 이동 거리, 회전 횟수
                      -> 예상 배터리 잔량(%)
```

역방향 의존은 없다. 배터리 예측이 경로를 바꾸지 않고, 경로 탐색이 위험 구역의 모양을 바꾸지 않는다. 나중에 "잔량이 부족하면 다른 경로를 찾는다"는 요구가 생기면, 그건 이번 합의에 없는 새 기능이다.

## 이번 단계에 없는 것

- 구현 코드, 의사 코드, 학습 스크립트
- 화면 배치와 조작 방식
- 센서 노이즈, 동적 장애물, 다른 로봇과의 충돌
- 위험 종류별 다른 비용
- 경로를 배터리에 맞춰 다시 고르는 최적화
