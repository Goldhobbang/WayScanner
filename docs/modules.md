# 모듈 경계

세 기능은 세 모듈이다. 서로 내부 계산을 공유하지 않고, 아래 결과만 넘긴다. 파일 이름, 함수 이름, 언어는 정하지 않았다.

## 위험 구역 모듈

담당: 팀원.

받는 것:

- 위험 점들의 위치 목록
- 점이 놓인 지도의 범위 (점이 지도 밖이면 어떻게 할지는 구현 전 합의)

내는 것:

- 금지 구역을 이루는 꼭짓점 목록. 순서는 다각형을 한 바퀴 도는 순서
- 점이 너무 적어 다각형이 안 되는 경우의 표시 (0개, 1개, 2개)

넘기지 않는 것:

- 어떤 순서로 점을 훑었는지
- 일반 장애물, 출발지, 목적지

경로 모듈은 이 다각형의 내부와 경계를 모두 "갈 수 없는 칸"으로 이해하면 된다. 위험 구역 안이나 경계 위에 출발지 또는 목적지가 있으면 경로를 실패로 처리한다. 스캔 과정을 알 필요가 없다.

## 경로 모듈

담당: 본인.

받는 것:

- 격자 지도
- 출발지, 목적지
- 일반 장애물
- 위험 구역 모듈이 낸 금지 다각형

내는 것:

- 성공 시: 출발지부터 목적지까지의 칸 순서
- 실패 시: 경로 없음. 이 경우 배터리 모듈을 호출하지 않는다
- 배터리 모듈이 쓸 두 값: 총 이동 거리, 방향 전환 횟수

넘기지 않는 것:

- 탐색 중에 버린 후보 경로
- 평가 함수의 중간 값

거리와 회전의 정의는 경로 모듈이 소유한다. 배터리 모듈은 그 정의를 바꾸지 못한다. 정의를 바꾸면 학습 데이터와 예측이 어긋나므로, 바꿀 때는 두 담당이 함께 적는다.

## 배터리 모듈

담당: 본인.

받는 것:

- 총 이동 거리
- 방향 전환 횟수
- 미리 준비된 선형 회귀 모델 (학습은 시뮬레이터 루프 밖)

내는 것:

- 목적지 도착 시 예상 배터리 잔량(%)
- 입력이 비었거나 경로가 없을 때의 표시. 숫자를 지어내지 않는다

넘기지 않는 것:

- 경로를 고치라는 지시
- 금지 구역을 줄이라는 지시

화면은 이 숫자(또는 예측 불가 표시)를 보여 주기만 한다. 화면이 모델을 다시 학습하지 않는다.

## 붙이는 순서

1. 위험 점이 정해진다.
2. 위험 구역 모듈이 다각형을 낸다.
3. 경로 모듈이 그 다각형과 장애물을 피해 경로와 두 특징값을 낸다.
4. 경로가 있을 때만 배터리 모듈이 잔량을 낸다.
5. 화면은 구역, 경로, 잔량을 같이 보여 준다.

한 모듈의 결과가 없으면 다음 모듈은 추측으로 채우지 않고 멈춘다.
